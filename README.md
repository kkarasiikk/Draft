# Life

Особистий застосунок: бюджет, а тепер і щоденні завдання — в одному місці.
PWA (Progressive Web App) без збірки: чистий HTML/CSS/JS + Firebase.

## Структура проєкту

```
index.html, home.js              -- домашній хаб (вибір розділу, тема, мова, експорт)
export-xlsx.js                   -- складання .xlsx-резервної копії (спільний для хаба)
service-worker.js                -- офлайн-кеш хаба (свій SW є в кожному модулі)
budget/                          -- модуль «Бюджет»: транзакції, заощадження, цілі, нотатки
goals/                           -- модуль «Цілі»: віхи, серії, щоденник, прогрес
tasks/                           -- модуль «Завдання»: підзадачі, теги, пріоритет
workout/                         -- модуль «Тренування»: сесії, прогресія, особисті рекорди
firestore.rules                  -- правила доступу Firestore (усі колекції, всі модулі)
firestore.indexes.json           -- складені індекси
firebase.json                    -- деплой: Firestore rules/indexes + Cloud Functions
index.js, ai.js, reminders.js    -- Cloud Functions (окремий Node-проєкт, package.json у корені)
.github/workflows/ci.yml         -- CI: перевірка синтаксису JS + тести Cloud Functions
```

Шапка модуля — тільки напис **Life** зліва вгорі (той самий, що на головній,
лише менший), і він же посилання назад на хаб. Глобальні налаштування —
тема, мова, вихід і **експорт даних** — живуть у меню головного екрана;
у модулях лишається тільки те, що стосується самого модуля: у «Бюджеті» це
кнопка «⋮» (валюта, категорії, імпорт CSV) і AI-помічник поруч, у
«Завданнях» — «⋮» з нагадуваннями й шаблонами.

Експорт у `.xlsx` зібраний в `export-xlsx.js`: він приймає дані параметром,
тож головний екран читає їх із Firestore разовим запитом, а не тримає в
пам'яті. Стандартні категорії винесені в `budget/categories-default.js` —
вони потрібні і бюджету, і експорту (доки людина не редагувала категорії,
у профілі їх немає, і у файлі були б службові id).

У всіх модулів однакова навігація: плаваюча нижня панель із вкладками й
круглою кнопкою «+» посередині (`.bottom-nav` у кожному `index.html`).
Групи вкладок ліворуч і праворуч мають однакову ширину, тож «+» лишається
рівно по центру, скільки б вкладок не було: 4 у «Бюджеті», 4 у «Завданнях»
(тиждень / календар / статистика / головна), 2 у «Тренуваннях»
(тренування / рекорди), 2 у «Цілях» (цілі / головна).

Кожен модуль (`budget/`, `goals/`, `tasks/`, `workout/`) — самодостатня сторінка зі своїм входом
(email/пароль), темою й мовою; профіль і сесія спільні (той самий Firebase
проєкт), тому вхід один раз на домашній сторінці не обов'язковий — можна
увійти прямо в модулі.

## Стек

- **Frontend** — чистий HTML/CSS/JS на сторінку, без фреймворків і без кроку збірки
- **Firebase Auth** — вхід через email/пароль
- **Cloud Firestore** — зберігання даних (транзакції, категорії, заощадження, нотатки, завдання)
- **Cloud Functions** — `walletSync` (прийом транзакцій з Apple Shortcuts),
  `aiChat` (AI-асистент у модулі «Бюджет»)
- **Firestore Security Rules** — `firestore.rules`
- **Service Worker** — офлайн-кеш статики, окремий на кожен модуль
  (`service-worker.js`, `budget/`, `goals/`, `tasks/`, `workout/`); для сторінки виграє
  реєстрація з найдовшим збігом scope, а кожен SW чистить лише власні кеші
- **PWA manifest** — окремий `manifest.json` на кожен модуль (свій `scope`/`start_url`),
  іконки в т.ч. `maskable`-варіанти для Android — спільні, лежать у `budget/`
- Зовнішні бібліотеки (з `cdnjs.cloudflare.com`, дозволено через CSP): Chart.js,
  DOMPurify (санітизація HTML нотаток), SheetJS/xlsx (експорт в Excel)
- Курс валют — публічне API НБУ (`bank.gov.ua`), кешується локально

## Локальний запуск

Це статичний сайт без білд-кроку — досить будь-якого локального HTTP-сервера
(відкрити напряму як `file://` не вийде через service worker і Firebase SDK):

```bash
npx serve .
# або
python3 -m http.server 8080
```

Потім відкрити `http://localhost:PORT` (домашній хаб) або одразу
`http://localhost:PORT/budget/` чи `http://localhost:PORT/tasks/`.

## Деплой

Проєкт налаштований на Firebase Hosting/Firestore/Functions (`firebase.json`):

```bash
npm install -g firebase-tools
firebase login
firebase use --add          # вибрати/додати свій проєкт, якщо ще не зроблено
firebase deploy
```

**Правила треба публікувати щоразу, коли в документі з'являється нове поле.**
`firestore.rules` перелічує дозволені ключі через `hasOnly(...)`, тож зі
старими правилами запис із новим полем відхиляється — застосунок показує
«Сервер відхилив запис: правила Firestore застаріли». Найшвидший спосіб:

```bash
firebase deploy --only firestore:rules
```

або вставити вміст `firestore.rules` у Firebase Console -> Firestore Database
-> Rules -> Publish.

Це задеплоїть `firestore.rules`, `firestore.indexes.json` і Cloud Functions
(`walletSync`, `aiChat`). Хостинг статичних файлів (GitHub
Pages чи Firebase Hosting) — окремо, залежно від того, де реально
розміщений сайт.

Для нагадувань потрібні ще дві речі в консолі, обидві разові:
**Project Settings -> Cloud Messaging -> Web Push certificates -> Generate key
pair** (ключ кладеться в `FCM_VAPID_KEY` у `budget/firebase-config.js`, він
публічний) і увімкнений **Cloud Scheduler API** — Firebase запропонує це сам
під час першого деплою `taskReminders`.

**Важливо:** вихідний трафік Cloud Functions вимагає, щоб проєкт
Firebase був на тарифі **Blaze** (pay-as-you-go). Без Blaze функції
`walletSync`/`aiChat` задеплоїти не вдасться. У межах
безкоштовних лімітів Blaze (2 млн викликів Cloud Functions на місяць)
звичайне особисте використання нічого не коштує.

## Конфігурація перед першим запуском

1. У `budget/firebase-config.js` вкажи конфіг свого проєкту Firebase
   (`apiKey`, `projectId` тощо — з Firebase Console → Project settings).
   Цей самий файл підключають і `index.html` (домашній хаб), і `tasks/index.html`.
2. Там же встав реальний **App Check reCAPTCHA v3 site key**
   (`RECAPTCHA_V3_SITE_KEY`) — без нього другий рівень захисту Firestore
   не активний. Отримати ключ: Firebase Console → App Check → reCAPTCHA v3.
3. Переконайся, що `.firebaserc` вказує на твій `projectId` (створи файл,
   якщо його ще немає — `firebase use --add` зробить це автоматично).

## Модель даних (Firestore)

```
users/{uid}                     -- профіль: lang, currency, categoriesIncome, categoriesExpense
users/{uid}/transactions/{id}   -- {type, amount, category, note, date}
users/{uid}/savings/{id}        -- {type, amount, currency, note, date, goalId}
users/{uid}/savingsGoals/{id}   -- {name, createdAt}
users/{uid}/pages/{id}          -- {title, content, createdAt, updatedAt}
users/{uid}/tasks/{id}          -- {title, notes, done, completedAt, priority, tags,
                                    dueDate, dueTime, estimateMin, recurrence,
                                    subtasks, createdAt, updatedAt}
users/{uid}/workouts/{id}       -- {date, name, notes, exercises: [{id, libId, muscle,
                                    name, sets: [{weight, reps}]}], createdAt, updatedAt}
users/{uid}/goals/{id}          -- {title, category, why, targetDate, status,
                                    milestones: [{id, title, done}], checkins: [YYYY-MM-DD],
                                    journal: [{id, text, createdAt}], createdAt, updatedAt}
```

Детальні правила доступу — у `firestore.rules`, складені індекси — у
`firestore.indexes.json` (там індекс `(type, date)` для `transactions`:
без нього запит `query_transactions` з `aiChat` падає з `FAILED_PRECONDITION`).

## Модуль «Цілі» (`goals/`)

- Довгострокові цілі з категорією (здоров'я, фінанси, навчання, кар'єра,
  стосунки, подорожі, творчість, інше), полем «навіщо тобі це» й
  необов'язковим дедлайном.
- **Віхи** — кроки всередині цілі; прогрес рахується як частка пройдених
  віх, наступна непройдена підсвічується як «наступна зупинка».
- **Серія (streak)** — щоденні відмітки «зробив крок сьогодні» (`checkins`),
  плюс **щоденник** коротких нотаток по цілі.
- Фільтр за станом: усі / активні / завершені / архів.

## Модуль «Завдання» (`tasks/`)

- Над списком дня — картка **«Зараз»** (лише коли обрано сьогодні): одна наступна дія (кнопка «Далі»
  гортає чергу), прогрес дня й чесний підсумок. Черга: спершу прострочене,
  далі сьогоднішнє, чий час уже настав, потім найближче за часом, потім
  сьогоднішнє без часу; завдання без дати підхоплюються, лише коли на
  сьогодні нічого не лишилось. Якщо сума оцінок перевищує час, що лишився
  до 22:00, картка про це попереджає — замість того щоб мовчки накопичувати
  невиконане. Логіка винесена в `tasks/now-queue.js` (чисті функції).
- Головний екран — **тиждень**: рядок із семи днів (крапка = на день щось
  заплановано, порожнє кільце = все виконано), під ним завдання обраного дня.
  Тиждень гортається і стрілками, і пальцем: числа їдуть за пальцем, бо в
  доріжці завжди відрендерені три тижні (попередній, поточний, наступний), а
  на відпусканні доріжка або доїжджає до сусіднього, або вертається назад.
  Жест працює й мишею на десктопі; тап по дню перемикає список. Відкривається завжди на сьогодні.
- **Календар місяця — окремий екран** (кнопка в шапці): потрібен, щоб
  планувати на далекі дати, тож не займає місце там, де людина буває щодня.
  Тап по дню повертає у тиждень уже з цим днем — і кнопка «+» додає саме
  на нього; місяці теж гортаються пальцем. Заголовок місяця перемикає на **річну сітку**. На телефоні
  завдання в клітинках показані крапками (колір = пріоритет): у 44 пікселі
  ширини влазить хіба що «Дз…», а кількість інформативніша за уривок назви.
- Завдання без дати — окремою секцією під списком дня; виконані згорнуті
  в блок «Виконано (N)».
- **Нагадування** (меню -> «Нагадування»): push у момент завдання («за 10 хв»,
  «за 30 хв», «за годину», «у час завдання»; для завдань без часу — о 9:00 або
  18:00) плюс два щоденні дайджести — ранковий план і вечірній підсумок.
  Клієнт рахує момент і кладе його в `reminderAt`; розсилає Cloud Function
  `taskReminders` (планувальник раз на 5 хвилин), бо браузер закритий саме
  тоді, коли нагадування найпотрібніше. Година дайджесту рахується в
  таймзоні користувача — сервер живе в UTC. Мертві токени прибираються
  на першій же невдалій розсилці.
  **На iPhone push працює лише для застосунку, доданого на домашній екран**
  (обмеження iOS, не наше).
- **Свайп по завданню** — вправо «виконано», вліво «на завтра». Слухач один
  на весь список (делегування), бо рядки перемальовуються на кожен снапшот.
  Смуга дії росте рівно на стільки, на скільки відʼїхав рядок: картки
  напівпрозорі, і суцільна смуга під рядком просвічувала б крізь нього.
- **«Маю час: 15 / 30 / 60 хв»** у картці «Зараз» — звужує ту саму чергу до
  того, що влізе в паузу. Повторний тап знімає обмеження.
- **Пошук** (іконка в шапці) — по назві, нотатці, тегах і підзадачах, по всіх
  завданнях одразу; кожне слово запиту має знайтись. У режимі пошуку тиждень,
  «Зараз» і список дня ховаються, результати згруповані за датою.
- **Шаблони** (меню -> «Шаблони», застосування — чипами у швидкому додаванні):
  готовий набір кроків, з якого одним тапом народжується звичайне завдання.
  Шаблон створюється з уже набраного завдання («Зберегти як шаблон» у формі),
  а не в окремому редакторі — так у ньому одразу правильні кроки, теги й
  оцінка. Звʼязку із застосованим завданням не лишається: зміна шаблону не
  переписує заднім числом те, що вже заведено. Ліміт — 12 шаблонів.
- **Розбір минулих днів** — невиконане з минулого не осідає мовчки: якщо є
  борги, зверху зʼявляється банер «З минулих днів лишилось N», а за ним екран,
  де кожен треба явно вирішити — на сьогодні, на завтра або «без дати»
  (це і є «відпустити», без видалення). Плюс «перенести все на сьогодні»
  одним тапом. «Пізніше» ховає банер до кінця дня, а не назавжди: завтра
  питання актуальне знову. Без цього ритуалу список за місяць стає кладовищем.
- **Статистика «Що я зробив»** (кнопка зі стовпчиками в шапці) — закрито
  сьогодні / цього тижня, серія днів поспіль, стовпчики за два тижні і
  список зробленого по днях. Плюс **особиста норма**: медіана закритих справ
  за активний день (`tasks/stats.js`, вікно 28 днів). Норма годує попередження
  в картці «Зараз» — замість «до 22:00 ще 8 годин» воно каже «заплановано 9,
  а зазвичай закриваєш 4». Поки історії мало, норма null і застосунок мовчить.
- **Швидке додавання** — кнопка на календарі (і на екрані дня) відкриває одне
  поле: `Купити молоко завтра о 18 #дім ~15хв !1`. Дата, час, тег,
  тривалість, пріоритет і повторення (`щодня`, `щосуботи`, `кожні 3 дні`)
  розбираються прямо з рядка, а що саме розпізналось —
  видно чипами ще до збереження. Розбір локальний (`tasks/quick-parse.js`),
  без мережі й без AI, тож працює офлайн і миттєво; розуміє всі 4 мови
  одночасно. Кнопка «Деталі…» переносить уже набране в повну форму.
  Тривалість вважається оцінкою тільки тоді, коли вона дописана з краю
  фрази (`Медитація 10 хв`, `30 хв на розтяжку`) або позначена `~`
  (`Виділити ~30хв, посидіти в тишині`). Усередині речення це звичайний
  текст: `Виділити 30 хвилин, посидіти в тишині` лишається назвою цілком,
  бо там «30 хвилин» — частина сенсу, а не позначка.
- У формі редагуються назва, нотатка, дата, час, **пріоритет, теги,
  підзадачі й оцінка часу** (`estimateMin`, 1–1440 хв).
- **Повторювані завдання** — щодня / кожні N днів, щотижня (з вибором днів:
  Пн/Ср/Пт), щомісяця того самого числа. Серія наперед не генерується:
  наступне завдання створюється в момент виконання поточного, тож виконане
  лишається в історії окремим записом. Пропущені повтори прокручуються в
  майбутнє — завдання, яке не робили місяць, не віддасть наступну дату теж
  у минулому. Галочка «рахувати від дня виконання» перемикає правило зі
  «щосуботи» на «кожні 7 днів після того, як реально зробив». Просте
  повторення задається і з рядка швидкого додавання; складніше
  (кілька днів тижня, свій інтервал) — у формі.
- Момент виконання зберігається в `completedAt` — на ньому будуватимуться
  історія й статистика.
- Сортування в межах дня — за часом, потім пріоритетом, потім назвою.

## Модуль «Тренування» (`workout/`)

- **Тренування** — сесії з довільною назвою й датою, кожна містить кілька
  вправ, кожна вправа — кілька підходів (вага × повторення). Вправи додаються
  або з невеликої вбудованої бібліотеки (13+ вправ, згруповані за м'язовою
  групою: груди/спина/ноги/плечі/руки/кор — назви локалізовані на всі 4 мови),
  або вручну довільною назвою.
- **Прогресивне навантаження** — при додаванні вправи, яку вже виконував(ла)
  раніше, форма одразу показує підказку «Минулого разу: 80×8», щоб не
  вигадувати вагу заново.
- **Особисті рекорди (PR)** — окрема вкладка «Рекорди» рахує по всій історії
  найважчий підхід для кожної вправи (з урахуванням оцінки 1ПМ за формулою
  Epley для коректного ранжування, коли вага та повторення відрізняються),
  групує за м'язовою групою і показує тренд «+X% від першого запису».
  Збереження нового рекорду одразу підсвічується тостом на екрані сесій.
- Тап на вправу в «Рекордах» відкриває історію: усі сесії з цією вправою в
  хронології, з позначкою 🏆 на записі, що є поточним рекордом.
- Дані зберігаються як масив вправ/підходів усередині документа сесії (як і
  підзадачі в `tasks/`) — без окремої підколекції на кожен підхід.

## AI-помічник (`aiChat`)

Модуль «Бюджет» → меню (гамбургер) → **AI-помічник**: чат, у якому можна
записати витрату словами («кава 80 грн») або спитати про свої фінанси
(«скільки я витратив на їжу цього місяця?»).

- Клієнт викликає Cloud Function `aiChat` (`firebase.functions().httpsCallable`),
  вона звертається до моделі Anthropic і має два інструменти:
  `add_transaction` (записати дохід/витрату) і `query_transactions`
  (порахувати суми за період) — цифри модель не вигадує, а бере з Firestore.
- Записана транзакція з'являється в списку сама — через той самий
  `onSnapshot`, що й будь-яка інша зміна даних.
- Ліміт: 30 повідомлень на 10 хвилин на користувача (`aiChatRateLimits`).
- Щоб це працювало, потрібні: тариф Blaze, задеплоєна функція
  (`firebase deploy --only functions`) і секрет `ANTHROPIC_API_KEY`
  (`firebase functions:secrets:set ANTHROPIC_API_KEY`). Поки функції немає,
  чат відповідає повідомленням «AI-помічник поки недоступний».

## Мови

Інтерфейс перекладений на 4 мови: українська, російська, польська, англійська
(`LANGS` та словники перекладів окремо в `home.js`, `budget/app.js`, `goals/app.js`,
`tasks/app.js`, `workout/app.js`).

## Резервне копіювання та імпорт даних

- Бюджет → Налаштування → «Експортувати в Excel (.xlsx)» — вивантажує всі
  дані користувача (транзакції, категорії, заощадження, цілі, нотатки) в
  один `.xlsx`-файл, повністю на клієнті, без додаткових запитів до Firestore.
- Бюджет → Налаштування → «Імпортувати транзакції з CSV» — масове додавання
  транзакцій з файлу `.csv` з колонками `дата, тип, категорія, сума, нотатка`
  (назви колонок і значення типу розпізнаються також англійською, російською
  і польською). Категорії, яких ще немає, створюються автоматично.

## Відомі обмеження / TODO

- Логіка сторінок (`home.js`, `budget/app.js`, `goals/app.js`, `tasks/app.js`,
  `workout/app.js`) автотестами не покрита — тести є лише для Cloud Functions
  і для парсера швидкого додавання, див. «Тести». Причина проста: код
  сторінок написаний як один скрипт на глобальних змінних, і щоб його
  тестувати, спершу треба виносити чисті функції в окремі файли — як це
  зроблено з `tasks/quick-parse.js`.
- `budget/app.js` розрісся до ~3000 рядків одним файлом — просився б поділ
  на модулі, але без кроку збірки це означає кілька `<script>` і спільний
  глобальний scope, тож поки лишається як є.
- `RECAPTCHA_V3_SITE_KEY` у `budget/firebase-config.js` — усе ще заглушка,
  тому App Check не активний (код це переживає, див. «Конфігурація»).
- «Завдання» — один спільний список без вкладених списків/проєктів;
  drag-and-drop немає, сортування автоматичне.
- «Тренування» — AI-коуч (аналіз прогресу мовою «схоже, що…» на основі
  історії тренувань) свідомо відкладений на наступний етап — MVP зараз
  лише трекінг + прогресія + рекорди, без звернень до `aiChat`. Немає
  також бібліотек/шаблонів тренувань, recovery-трекінгу (сон/RPE) і
  інтеграції з Apple Health/Garmin.
